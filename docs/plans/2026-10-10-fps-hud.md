# Full-screen Speedster HUD

**Goal:** Replace the embedded dashboard with the familiar FPS HUD specified by the user, while providing portable HTML, CSS and a small framework-free JavaScript controller.

**Design:** A full-viewport canvas with circular heading-up radar at top-left, distance/bolts at top-center, fading events at top-right, health/energy at bottom-left and speed/top speed at bottom-right. Use the existing fonts, white numerals, amber key values, blue energy, translucent black panels and CSS variables. Keep the center clear during play. Put map switching, graphics, fullscreen and controls in the Escape menu. Display the start hint briefly, then hide it. Preserve mobile prototype files and unrelated pending gameplay edits.

**Implementation:**
1. Add behavior checks for heading-up radar projection and bounded, expiring event messages; add browser checks for a full-size canvas, readable nonoverlapping corner panels, keyboard pause and map switching.
2. Add `src/hud/hud-overlay.html`, `hud-overlay.css`, and `hud-overlay.js`, with a documented `update` API using km/h for speed and meters for distance.
3. Replace `src/game-layout.js` and its CSS with an overlay adapter that preserves existing game listeners and supplies stats from both maps. Expand the outer player to fill the browser, moving its toolbar actions into pause.
4. Add optional heading-up rotation to the existing minimap renderer. Retain the 1.5 km span, retina backing canvas and fixed player marker size.
5. Connect the live game stats and events; suppress the parkour aiming reticle in this HUD. Keep existing gameplay intact.

**Validation:** Run the new behavior tests and existing game tests, inspect gameplay at desktop/phone/landscape sizes, confirm the canvas matches the viewport, check the empty center, hint expiry, low-health color, full/boost energy pulse, high-speed scale, radar rotation, pause/resume, fullscreen and switching maps. Build both browser and mobile bundles to catch shared-code regressions.
